# 0002 — 删除和移动的撤销／重做

**Date:** 2026-10-15
**Status:** Accepted (user approved; implemented)

## Problem Statement

图形删除、单图形拖动和组合移动没有历史记录，用户无法恢复误操作。集合修改已统一进入仓库，但单图形移动直接调用 ShapeVisualBase.Translate，需要在模型层提供可观察的移动结果。

## Proposed Solution

每个 SketchBoardDataManager 实现独立的 IShapeHistory，维护有上限的撤销和重做栈。该接口独立于 IShapeRepository，现有自定义仓库无需新增成员。删除记录保留原对象、原索引、组对象和选择；移动保存精确的前后模型状态和附加文字，恢复时不依赖反向位移或导出 DTO。Translate 发布移动结果，鼠标交互及批量删除使用可嵌套事务合并记录。

```mermaid
flowchart LR
    UI[鼠标 / 快捷键 / 工具栏] --> T[画板历史事务]
    T --> R[仓库删除 / 图形 Translate]
    R --> H[每画板 Undo / Redo 栈]
    H --> S[原对象恢复 / 前后状态恢复]
    S --> V[现有通知和渲染流程]
```

第一版覆盖单个／批量删除、清空、单图形移动和组合移动。每次拖动只记一步，点击及零位移不记录；Esc、捕获丢失或卸载结束当前事务，保留已发生的移动供撤销。撤销后新编辑清空重做栈，重放期间不产生新记录。文本输入框保留自己的快捷键行为。

新增绘制、缩放旋转、属性几何编辑、组合／解组、图层重新分配暂不记录；这些操作使已有历史失效，避免跨越未记录的模型变更恢复错误状态。锁定、图层显示隐藏、选择及视口缩放不写入历史。恢复不受当前锁定和显示状态阻止。自定义移动图形通过虚方法提供状态适配；未适配的移动使历史失效。历史仅驻留内存，默认最多 100 步。

## Alternatives Considered

- 全画板序列化：导出数据不完整，会丢失身份、组关系和外部引用，且拖动成本高。
- 反向位移：简单，但连续运算可能无法精确恢复 double 坐标，不适合作为通用状态恢复。

## Impact Assessment

新增历史接口、图形移动状态接口、仓库历史实现和工具栏命令。无新依赖、外部服务、持久化或基础设施变更。复用现有 WPF Dispatcher 和渲染流程。

## Acceptance Criteria

- 删除后撤销恢复相同对象、叠放顺序和原组关系，再次重做删除成功。
- 批量删除和连续鼠标移动各只产生一个历史步骤。
- 单图形及组合移动撤销／重做精确恢复坐标和附加文字，保留 Transform。
- 无位移、无效操作不产生记录；画板之间历史独立。
- 新编辑清空重做；重放不自我记录；历史条数有上限。
- Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z 与工具栏可用状态同步，文本编辑不被抢占。
- 自动化测试覆盖核心历史、交互边界及现有功能回归。
